# Pi Smart Hub — Definition of Done

Acest document definește condițiile de livrare pentru produsul finit din [PRODUCT.md](PRODUCT.md). „Funcționează pe desktop” sau o captură de mockup nu dovedește funcționarea pe țintă. Criteriile legate de hardware se verifică pe Raspberry Pi 4 4 GB cu panoul DSI 7 inchi, 800 × 480, landscape. Implementarea este importată; criteriile rămân pentru acceptarea unui candidat identificat. BOOT-01/02 descriu runtime-ul actual cu sesiune desktop; ADR-0004 cere revizuirea lor explicită pentru viitorul appliance.

## Regula de acceptare

Un criteriu este PASS doar cu dovada indicată și cu build-ul candidat identificat. Rezultatul general este DONE când toate criteriile necesare sunt PASS, configurația țintă este documentată, iar nicio limitare externă nu este prezentată în UI drept funcționalitate disponibilă. Un serviciu declarat imposibil/nesuportat rămâne OPEN până când se aprobă o alternativă de produs și aceasta trece aceleași verificări de UX și instalare.

| ID | Arie | Condiție de acceptare | Dovadă necesară |
|---|---|---|---|
| HW-01 | Țintă | Modelul Pi, memoria, OS/build-ul, firmware-ul, panoul/driverul, rezoluția și orientarea reale sunt consemnate; aplicația rulează la 800 × 480 landscape fără decupare. | Fișă de configurare cu versiuni și capturi de ecran de pe panou. |
| UX-01 | Atingere | Toate acțiunile principale se pot executa tactil; țintele interactive au minimum 48 × 48 px, controalele periculoase sunt separate, iar tastatura și dialogurile rămân în viewport. | Măsurători/captura UI și tur tactil filmat sau checklist pe dispozitiv. |
| UX-02 | Aspect | Acasă, setări, dialoguri și stări goale/încărcare/eroare au ierarhie coerentă, fără suprapuneri, clipping, ecrane goale neintenționate ori scroll accidental pe panourile de bază. Capturile-cheie sunt la exact 800 × 480 pentru fiecare limbă și temă. | Set de capturi 800 × 480 pentru ecranele și stările cheie în română/engleză și temele E-Ink/noapte; notă de revizie vizuală pe ținta reală. O captură redimensionată de desktop nu trece criteriul. |
| UX-03 | Lizibilitate | Textul de bază are minimum 16 px, textul secundar în mod normal minimum 14 px; contrastul textului este minimum 4.5:1 (3:1 pentru text mare), iar limitele și stările controalelor interactive au contrast de minimum 3:1. Culoarea nu este singurul indicator. Animațiile nu blochează comenzile și există mod de noapte/screensaver configurabil. | Verificare pe dispozitiv zi/noapte, capturi și măsurători de font/contrast pentru fiecare temă; probă de reducere/dezactivare a mișcării dacă este oferită. |
| I18N-01 | Română/engleză | Fiecare ecran, eroare, dialog, stare de progres și etichetă este disponibilă în română și engleză; nu rămân chei brute sau texte trunchiate. Schimbarea limbii se aplică imediat și persistă după repornire. | Inventar de ecrane în ambele limbi, tur capturat și probă de repornire. |
| I18N-02 | Formate locale | Ora, data, unitățile meteo și formatarea numerelor urmează setările locale selectate; fusul orar și trecerea datei sunt corecte. | Probă pentru ambele limbi, fusul orar configurat și schimbarea zilei/orei simulată sau verificată. |
| HOME-01 | Acasa | Ceasul și data sunt corecte; starea datelor meteo și momentul ultimei actualizări sunt vizibile; cardul principal, scurtăturile și starea rețelei/audio/Bluetooth se actualizează când sursa se schimbă. | Capturi cu stări normale și schimbate, plus jurnal de verificare cu momentele observate. |
| HOME-02 | Vreme | Furnizorul și condițiile de utilizare sunt documentate; sunt afișate condiția curentă și prognoza convenită; fără internet, cu răspuns invalid sau date expirate, UI arată starea și păstrează ultima stare cache-uită fără a o prezenta ca actuală. | Test online, offline, răspuns eșuat și recuperare; capturi și setarea furnizorului. |
| SET-01 | Preferințe | Limba, tema, noaptea, screensaverul, volumul și celelalte preferințe declarate se salvează și se reîncarcă după restart și oprire normală; valorile implicite sunt utilizabile. | Matrice preferință → restart → valoare restaurată, cu capturi. |
| SET-02 | Teme | Tema E-Ink și tema nocturnă acoperă toate ecranele, stările, dialogurile și controalele; accentul nu reduce lizibilitatea; schimbarea temei nu resetează setările sau navigarea. | Set capturi comparabile pentru fiecare ecran și probă de schimbare/persistență. |
| NET-01 | Configurare inițială | La prima rulare, ghidul de întâmpinare poate fi parcurs integral; conectivitatea este verificată; Wi-Fi/Ethernet, eșec, retry, skip și continuarea ulterioară au rezultate explicite. | Tur complet de setup și probe distincte de succes/fără rețea/eșec de autentificare. |
| NET-02 | Securitate rețea | Parolele nu apar după salvare în UI, jurnale, fișiere de diagnostic sau commit-uri. Utilizatorul poate schimba și elimina conexiunea salvată prin setări. | Inspecția fișierelor/jurnalelor generate și demonstrație de editare/eliminare. |
| NET-03 | Degradare | Oprirea rețelei nu blochează navigarea locală sau setările; starea se actualizează, operațiile dependente oferă retry și serviciile se recuperează după reconectare. | Probă de întrerupere, utilizare offline și revenire; jurnal cu timpi și capturi. |
| MEDIA-01 | Radio | Posturile configurate pot fi selectate, pornite/oprite; se afișează starea reală; buffering, URL invalid, lipsa internetului și recuperarea sunt tratate clar. | Cel puțin două fluxuri publice permise, inclusiv un eșec intenționat; capturi și jurnal audio. |
| MEDIA-02 | Fișiere locale | Utilizatorul poate găsi și reda fișiere din locațiile aprobate, folosi controalele prezentate și vedea formatul invalid sau fișierul lipsă fără blocarea aplicației. Formatele suportate sunt publicate. | Set de fișiere de test pentru fiecare format declarat, navigare și cazuri de eroare pe Pi. |
| MEDIA-03 | Volum/audio | Sliderul și comenzile de volum modifică ieșirea efectivă; mute/unmute și dispozitivul curent au stare vizibilă; schimbarea ieșirii sau lipsa ieșirii este gestionată fără volum UI înșelător. | Măsurare/probă auditivă la ieșirea selectată și test de mute, nivel și lipsa dispozitivului. |
| BT-01 | Bluetooth | Din aplicație se poate porni scanarea, selecta o boxă, asocia, conecta, deconecta, reconecta explicit, uita și vedea starea dispozitivului; timeout/refuz și dispozitiv dispărut au explicații și retry. Nu se conectează automat un dispozitiv nou necunoscut. | Probă completă cu boxă Bluetooth fizică, capturi, versiuni/identificatori de dispozitiv și caz de eșec. Simulatorul nu înlocuiește această probă. |
| BT-02 | Audio Bluetooth | După conectare, sunetul unei surse media se aude pe boxa selectată; redirecționarea, volumul, deconectarea și revenirea la ieșirea anterioară se comportă conform stării UI. | Probă cap-coadă cu radio și fișier local pe boxă fizică, apoi deconectare/revenire. |
| EXT-01 | YouTube | Soluția aleasă este permisă de termenii/politicile curente, păstrează playerul și experiența cerută, funcționează pe Pi-ul țintă și explică limitările de cont/rețea; dacă nu există redare integrată suportată, alternativa externă este explicită și testată. | Link la politica revizuită, notă despre calea tehnică, probă playback/alternativă pe Pi și revizuire a brandingului/controalelor. |
| EXT-02 | Netflix | Calea de acces, browserul/runtime-ul, autentificarea, DRM și rezoluția practic disponibilă sunt verificate pe hardware-ul și OS-ul țintă. Un shortcut nu se numește player dacă doar deschide un site. | Caz real cu cont autorizat pe Pi sau decizie de produs semnată pentru alternativă; capturi și limitări documentate. |
| EXT-03 | Muzică | Este ales serviciul final; dreptul de integrare, login, planul de cont, suportul ARM/Linux, playback, controalele și condițiile comerciale sunt documentate și trec pe țintă. | Decizie de serviciu, linkuri la condiții oficiale, probă cont autorizat pe Pi sau alternativa aprobată și probată. |
| BOOT-01 | Pornire | După alimentare și pornirea sesiunii grafice, hubul pornește automat în full-screen; splash-ul nu rămâne blocat; inițializarea ajunge într-o stare utilizabilă cu sau fără rețea. | Minimum 5 porniri la rece, timpi notați, capturi/video și jurnal pentru un boot offline. |
| BOOT-02 | Revenire | După închiderea aplicației, utilizatorul revine controlat la desktop; atingerea accidentală nu închide instant aplicația; lansarea din nou restabilește o stare coerentă. | Probă ieșire, anulare confirmare și relansare. |
| REL-01 | Stabilitate | O sesiune de utilizare continuă de cel puțin 8 ore nu produce blocaj, creștere necontrolată a memoriei, pierderea comenzilor tactile sau degradarea animațiilor. | Jurnal de sesiune, utilizare memorie la început/final și checklist periodic de interacțiune. |
| REL-02 | Recuperare | Oprirea neașteptată a procesului nu corupe preferințele; lansatorul repornește aplicația sau oferă un mesaj recuperabil; logul păstrează cauza utilă fără secrete. | Oprire controlată pentru test, revenire automată/manuală și inspecția configurației/logului. |
| PERF-01 | Răspuns | Pe Pi-ul țintă, feedback-ul vizual local apare în cel mult 100 ms, navigarea locală are latență p95 de cel mult 300 ms, iar ecranul Acasă devine utilizabil în cel mult 10 s de la pornirea sesiunii grafice, independent de rețea. Măsurarea nu include așteptări declarate pentru rețea/terți. | Raport pe build-ul candidat: minimum 30 de interacțiuni locale pe tip de acțiune pentru p95 și feedback, plus minimum 5 lansări pentru timpul Acasă; cronometraj monotonic, build și condiții consemnate. |
| PERF-02 | Resurse | În build-ul de producție, memoria PSS combinată a aplicației și tuturor proceselor Chromium este cel mult 700 MiB în idle, măsurată la 2 minute după ce Acasă devine utilizabil. Sistemul de 4 GB rămâne funcțional, iar redarea video/audio nu face UI-ul inutilizabil. | Raport PSS cu PID/proces și condiții la idle; separat se consemnează memoria în fiecare scenariu media și utilizarea sistemului, fără a confunda acestea cu pragul idle. |
| DIAG-01 | Jurnale | Logurile sunt rotite, au nivel configurabil pentru diagnostic și nu înregistrează parole, tokenuri sau date personale inutile; utilizatorul poate obține un pachet de diagnostic fără secrete. | Revizuirea logurilor pentru scenarii reprezentative și verificarea conținutului pachetului. |
| DEL-01 | Instalare | O instalare curată pe configurația suportată poate fi făcută urmând documentația; dependențele, licențele și pașii de configurare sunt complete; actualizarea și revenirea la versiunea precedentă sunt descrise și probate. | Repetarea procedurii pe imagine curată, checklist, inventar de licențe/dependențe și probă de rollback. |
| DEL-02 | Livrare | Sunt consemnate versiunea aplicației, build-ul, configurația testată, limitările cunoscute, sursele meteo/servicii, procedurile de instalare, backup, restaurare și ieșire la desktop. Nu există secrete sau fișiere de audit personal în pachetul livrat. | Release notes, manifest/checksum, backup/restore probe și revizie finală a pachetului. |

## Matricea finală a fluxurilor

Release review-ul parcurge toate fluxurile următoare pe build-ul candidat, în română și engleză, la 800 × 480, cu verificare vizuală în fiecare temă. Capturile generate pe desktop pot ajuta la inspecția layoutului, dar nu înlocuiesc probele tactil/audio și capturile panoului Pi:

1. Pornire rece → splash → configurare inițială → acasă, atât online, cât și offline.
2. Acasă → vreme → eroare de rețea → reconectare → date actualizate.
3. Acasă → radio → volum → pauză/opriere → indisponibilitatea fluxului.
4. Acasă → fișier local → controale → format invalid/lipsă.
5. Aplicație → scanare Bluetooth → asociere/conectare boxă → redare → deconectare/uitare.
6. Acasă → setări rapide → limbă/temă/noapte/volum → restart → preferințe restaurate.
7. YouTube, Netflix și serviciul de muzică: fiecare pornește exact calea descrisă în UI și trece criteriul EXT aferent.
8. Ieșire către desktop → anulare → confirmare → relansare.

## Evidență de release

La evaluarea finală se păstrează un dosar pentru build-ul candidat cu: matricea de mai sus marcată PASS/FAIL/OPEN, configurația Pi, capturile de pe ecranul real, înregistrările testelor tactile/audio, jurnalele redactate, sursele oficiale pentru serviciile externe și pașii repetați de instalare/restaurare. Orice OPEN are proprietar, motiv concret și decizie de produs; DONE nu se declară cât timp un criteriu obligatoriu este OPEN.
