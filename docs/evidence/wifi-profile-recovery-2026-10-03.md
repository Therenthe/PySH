# Saved Wi-Fi credential recovery

The previous UI always created a new connection when entering a password. It now selects a single matching saved Wi-Fi profile explicitly by UUID, or asks which saved profile to use when several have the same SSID. Saved profiles also have a Change password action. Cancellation does not submit a request; Forget requires a separate confirmation. Names and SSIDs remain distinct. Password values are masked and never returned by status.

Backend updates the selected profile in memory using Update2(0x2), activates the same profile, and persists after activation succeeds. Existing settings, PSK, autoconnect and IP configuration are preserved. Failure restores the snapshot before checkpoint rollback; unverified recovery produces network_recovery_failed. Unknown/mismatched/ambiguous UUIDs are refused; credentials managed by external secret agents or unsupported security types are refused before mutation. Original profiles are never deleted by password updates. Connect/forget transactions are serialized. API profile_id is optional for new networks and validated as a UUID.

Protocol reference: [NetworkManager Settings.Connection](https://www.networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Settings.Connection.html). GetSettings excludes secrets; GetSecrets is requested separately. In-memory updates retain the persistent profile; Save persists changes. 0x8, which can remove disk data, is not used.
